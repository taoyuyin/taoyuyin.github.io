从知识表示到企业 AI：本体（Ontology）的发展、演进与产业实践

发表于 2026-10-08

如果把企业数字化的发展过程拉长来看，会发现一个很有意思的现象：

企业过去一直在解决“数据存在哪里、怎么计算、怎么查询”的问题，而本体开始解决的是“这些数据究竟代表什么，以及它们之间是什么关系”的问题。

ERP、CRM、MES、WMS、SRM、数据仓库、数据湖解决了企业数据的采集、存储和计算；数据治理解决了数据标准、质量、元数据和责任；知识图谱进一步把数据组织成关系网络；而本体（Ontology）则试图在这些技术之上建立一套机器可以理解、推理和复用的业务世界模型。

近年来 Palantir 将 Ontology 提升到企业操作系统和 AI Agent 的核心位置，又让这个原本主要存在于 AI、知识工程和 Semantic Web 领域的概念重新成为企业数据架构的重要话题。Palantir甚至直接将 Ontology 定义为企业的数字化表示，并将对象、关系、动作、逻辑和安全纳入其中。(Palantir)

但需要特别注意：

今天企业讨论的 Ontology，并不是一个突然出现的新概念。

它已经经历了三十多年从知识表示 → Semantic Web → 知识图谱 → 企业语义层 → 企业 Ontology → AI/Agent Ontology的演进。

下面把这条发展路线完整梳理一下。

二、Ontology 最初来自知识表示和 AI

Ontology 并不是互联网时代才出现的。

哲学中的 Ontology 本身是“本体论”，研究：

世界上有什么东西，它们是什么，以及它们之间是什么关系。

进入计算机科学以后，这个概念被引入知识表示（Knowledge Representation）和人工智能。

1993 年，Thomas Gruber 在论文 A Translation Approach to Portable Ontology Specifications 中给出了后来被广泛引用的定义：

ontology 是对一个共享概念体系的形式化、明确的规范。

它关注的是：

也就是说，不只是定义“有什么数据”，而是定义：

Gruber 当时的重要背景就是希望让不同 AI 系统之间能够共享和复用知识。(Tom Gruber)

所以从本质上讲：

Ontology 最初解决的是“知识如何被机器形式化表达”的问题。

二十三、一个更值得关注的趋势：Ontology 正在从“知识模型”变成“企业操作模型”

这是我认为理解未来企业数据架构最重要的一点。

过去：

解决：

企业发生了什么？

后来：

解决：

企业的数据之间是什么关系？

现在进一步：

开始解决：

这就是 Ontology 从传统知识工程走向 AI Agent 时代最大的变化。

其中：

数据仓库负责：

二十五、最后：不要把 Ontology 理解成“又一个数据平台”

如果把 Ontology 简单理解成：

“知识图谱升级版”

其实低估了它。

更准确的理解应该是：

Ontology 是企业对现实业务世界的一套机器可理解的模型。

它的演进路径其实非常清晰：

因此，Ontology真正解决的长期问题并不是“如何把数据变成图”，而是如何把企业中分散在 ERP、MES、CRM、数据仓库、文档、规则和业务流程里的隐性业务认知，逐渐变成一套机器可以理解、查询、推理和执行的显式模型。

这也是为什么它会在 AI Agent 时代重新变得重要：过去 Ontology 的主要消费者是知识系统，而现在它的消费者开始变成AI Agent。

甚至到了 2026 年，Palantir 已经把 Ontology MCP 推向 GA，使 Agent 可以通过 MCP 访问 Ontology 中的企业对象和动作，这说明 Ontology 正从传统的知识建模技术进一步走向 Agent 的企业语义与行动接口。(Palantir)

从这个角度看，Ontology 很可能成为未来“数据仓库 → Semantic Layer → AI Agent”这条演进链条中的关键一层。
